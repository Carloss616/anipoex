# Extension runtime: match Mihon's host

Extensions run against whatever the host puts on the classpath, so the host follows Mihon.

- **Libraries and versions come from Mihon's [`gradle/libs.versions.toml`](https://github.com/mihonapp/mihon/blob/main/gradle/libs.versions.toml)** (coroutines, OkHttp, jsoup, QuickJS, imagedecoder), capped only where a version needs a Kotlin compiler past the app's. A `NoSuchMethodError` or `NoClassDefFoundError` from an extension means the host is behind (`runBlockingK` came from coroutines 1.11).
- **Network classes are ports of Mihon's** (`@see` at the top of each); diff against the upstream file before changing behaviour. The client keeps cookies (`AndroidCookieJar`), and Android solves Cloudflare in a WebView. The JVM's `CloudflareInterceptor.jvm.kt` asks the app through `Host` (desktop: `desktop/challenge.js`; iOS: `ChallengeHost.swift`): the browser solves as itself, and that host's requests then go out from the solved page, since some sites tie the clearance to the browser's TLS fingerprint and refuse it from the JVM or curl. Never rewrite the challenge browser's user agent: Electron's with the `Electron/` token stripped reads as spoofed (no matching client hints) and Turnstile then refuses even a person's click; the stock one clears a challenge on its own in ~4 s.
- **What the JVM can't run, the app lends through `Host`**: `QuickJs` evaluates in the app's own engine (`desktop/javascript.js`: an isolated world per engine in a hidden page with no network; iOS `ScriptHost.swift`: a `JSContext`), since QuickJS's JNI library can't load there and pure-Java engines (Rhino) don't parse the `class` syntax sites' scripts use. Android's crypto names the JVM lacks get a provider (`Pkcs7Padding.kt`: the extensions' AES helper asks for `AES/CBC/PKCS7PADDING` and swallows the failure). `android.graphics` keeps no pixels: a `Bitmap` is its encoded image plus the draws recorded on it, and `compress()` hands them to the app in one `renderImage` call (`ImageEngine.kt`; desktop `graphics.js`, a hidden page's canvas; iOS `GraphicsHost.swift`, Core Graphics), since the iOS JDK is java.base only. `android.webkit.WebView` drives a page the app owns through the `wv*` calls (`WebView.kt`; the page's side comes back as long-polled `wvEvents`), and `Dispatchers.Main` is the main `Looper`'s thread (`MainDispatcher.kt`), so the extensions' WebView helper runs as on Android and its Chromium probes fail into its fallbacks. Bot checks (Turnstile) inside those pages pass only if the browser looks like what it claims: desktop intercepts through the DevTools `Fetch` domain, never `protocol.handle` (its forwarded requests lose their `Sec-Fetch-*` headers), and gives an extension's user agent matching client hints (`webview-protocol.js` `uaOverride`); iOS keeps Safari's user agent when an extension asks for Chrome's, and can't hold requests, so it only reports navigations and the page's fetch/XHR. Cookies a page gains after it finished (a site's session) reach the CookieManager through `cookies` events.
- **dex2jar's output needs repairs before the JVM loads it** (`DexTranslator.kt`, one test per case): R8's inlined constructors, `java/util/Object` in frames, and static or private calls to an interface's method written as a class's (those classes go to version 52; measured on current APKs: one class in 142, none broken).
- **Reader pages go through the source**, as Mihon's `getImage`: the runtime's `image` call downloads with the source's client and `imageRequest` into `PageCache.kt`, and the reader shows that file (desktop: main's `anipoex-page://` scheme serves it). Never show a page's `imageUrl` directly: descramblers (keyed on a URL fragment such as `#scramble`, or in a client interceptor) only run there.
- **Covers go out with the source's `HttpSource.headers`**, as Mihon's `MangaCoverFetcher` does: some image hosts refuse a request without the site's Referer. `installed()` hands them per source; desktop adds them in main (`desktop/covers.js`), since headers on a web `<img>` make it a CORS fetch. On Android, Glide's `GlideUrl` loader is the runtime's client (DNS over HTTPS, cookies).
- **Measure parity on the catalog, not one source**: scan the index's jars for classes the runtime lacks, and run install + popular + search across a language (`jvm/tools/smoke-install.ts` covers install).
