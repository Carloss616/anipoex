# Anipoex OKF bundle

An [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format)
(v0.2) knowledge bundle for the **Anipoex** domain: a manga tracker on Expo (iOS,
Android, web) that reads and writes the signed-in user's [AniList](https://anilist.co)
list and, later, reads chapters from installable sources.

# What's here

Each `.md` file is a **concept**; its path without `.md` is the concept ID.
`index.md` files give progressive disclosure; `log.md` records history.

```
okf/
├── index.md       # bundle root — start here
├── overview.md    # the product on one page, the daily flow, the vocabulary
├── log.md         # update history, newest first
├── concepts/      # domain ideas and rules (list entry, statuses, tracking rules, sources…)
├── operations/    # every AniList GraphQL operation the app sends (src/**/*.gql)
├── stores/        # every piece of state the app keeps on the device
└── metrics/       # figures computed on read (list counts, reading progress)
```

There is no database of our own: the record of truth is AniList, reached through the
operations, and the device only keeps a session, a cache and a few preferences. So the
role a `tables/` folder plays in a backend bundle is split between `operations/` (what
we read and write remotely) and `stores/` (what we keep locally).

# Source of truth

**This bundle owns the domain**: what an entity, field, status or rule *means*.
`AGENTS.md`, `docs/app-structure.md` and `.claude/rules/` own the engineering (folder
layout, platform files, native UI) and point here instead of repeating it.

Pages are written against the code on 2026-10-18 (`src/**/*.gql`, `src/state/`,
`src/features/*/state/`, `src/features/*/utils/`) and AniList's public schema
(`schema.graphql`, generated by codegen). Anything marked **scaffolding** is mocked in
the app today and says so.

**When an operation, a store or a domain rule changes, update its page and add a
`log.md` entry in the same change.** `.claude/rules/okf.md` carries that rule and loads
when those files are touched.

# Consuming it

- Read it in any editor or on GitHub; cross-links are bundle-relative, so they form a graph.
- Feed it to an agent as domain grounding. There is no SDK; it's just files.
